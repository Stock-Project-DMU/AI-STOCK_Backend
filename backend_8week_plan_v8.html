백엔드 개발 계획 — feature/simulation 2단계 분리 반영

3~4주차(chore/admin-entity-update, feature/ls-websocket, feature/stock-price)가 실제로 완료되어 ✓ 완료 표시로 갱신했습니다. LS증권 연동은 ls.mode (real/mock) 프로퍼티로 배포·CI 환경에서 안전하게 전환되는 구조로 마무리됐습니다. 또한 Tavily API를 네이버 뉴스 검색 API로 교체했습니다 — 같은 검색어도 호출할 때마다 결과가 크게 달라지는 비일관성 문제가 실측으로 확인되어, 정제된 뉴스 인덱스를 쓰는 네이버 뉴스 API로 바꿨습니다. 이에 맞춰 AI 맞춤 시황 브리핑에 뉴스사(언론사) 선택 기능도 추가했습니다. 이번 v8에서는 feature/simulation을 2단계로 분리했습니다 — feature/ai-planning PR이 아직 dev에 병합되지 않은 상태(반려 후 재작업 중)라, 외부 API 연동 없이 완성 가능한 범위(DB·계산엔진·조회 API)만 먼저 진행하고, Gemini/DART 연동이 필요한 부분은 별도 브랜치로 분리했습니다.

무엇이 바뀌었나 (1~2주차, 이미 완료)

이전 계획은 project-init 하나가 끝나야 다음 사람이 시작할 수 있다고 가정해서 B·C가 1~2주차를 통째로 대기했어요. 하지만 실제로는 project-init 이후 db-entity · jwt-common · redis-config · common-response · websocket-config 는 서로를 필요로 하지 않는 완전히 독립된 작업이에요. 이 5개를 1주차에 동시에 나눠 배정해서 대기 시간을 없앴고, 이 부분은 이미 완료되어 변경하지 않습니다.

무엇이 바뀌었나 (6주차 feature/simulation, v8 신규)

feature/simulation은 원래 "본인의 ai-planning(5주차)에서 만든 클라이언트(Gemini/DART/ 네이버뉴스)를 재사용"할 계획이었는데, feature/ai-planning PR이 코드 리뷰에서 반려되어 아직 dev에 병합되지 않았습니다(재작업 후 재검토 예정). 그 클라이언트들은 현재 dev 기준으로는 빈 스텁이라 지금 당장은 재사용할 수 없습니다. 그래서 6주차 feature/simulation을 두 단계로 나눴습니다 — 1단계(feature/simulation)는 외부 API 연동 없이 완성 가능한 부분(Simulation 엔티티에 investmentAmount 컬럼 추가, 복리 계산·clamp·목표도달일 산출을 담당하는 계산엔진, 조회 전용 GET API)만 담당하고, 2단계(feature/simulation-integration)는 Gemini 호출·DART 재무제표·네이버 뉴스 연동이 필요한 POST /api/simulations(실제 시뮬레이션 실행)를 담당합니다. 2단계는 feature/ai-planning이 dev에 병합된 이후 착수합니다 — 같은 6주차 A 자리에 함께 배치해뒀지만, 실제 착수 시점은 ai-planning 재검토 완료 여부에 달려 있어 유동적입니다.

관리자 페이지·문의 기능의 DB/Redis 상세 설계는 schema.sql · redis-logic.md(v5) · CLAUDE.md · NAMING.md 4개 문서에 설계되어 있습니다. 단, 이 문서들을 실제 저장소 파일로 교체·커밋했는지 각자 브랜치 시작 전에 반드시 확인하세요 — 문서만 만들어두고 실제 파일 교체를 안 하면 코드에서 참조할 근거가 없는 상태로 작업을 시작하게 됩니다. 이 계획표는 담당자 배분과 주차별 일정만 다루며, 세부 컬럼·Enum·Redis 키 목록은 위 문서를 참고하세요.
01 — 독립 작업부터 먼저 (1~2주차)
project-init만 끝나면 db-entity·jwt-common·redis-config·common-response·websocket-config는 서로 필요 없이 동시에 시작 가능합니다.
02 — 3주차부터 A/B 트랙 교체
A는 실시간·AI 트랙, B는 주문·계좌 트랙을 맡습니다. 1~2주차 결과물은 트랙과 무관하게 서로 공유해서 재사용합니다.
03 — 6주 개발 + 1주 관리자 + 2주 통합
기존 21개 브랜치는 6주에 끝내고, 관리자 페이지·문의 기능을 7주차에 신설, 남은 2주(8~9주차)는 통합 테스트·버그 수정에 집중합니다.
